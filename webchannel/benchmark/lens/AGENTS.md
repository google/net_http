# Lens benchmark instructions

When changing or generating files under this directory, follow [README.md](README.md) and the [Lens benchmark specification](https://github.com/google/net_http/blob/main/webchannel/objc/demo/WebChanneliOSDemo/DESIGN.md#d-lens-latency-mimic--shutter-benchmark-mode).

- Write reports in English. Each run's `report.md` must link the specification and record the physical-device environment, network switch states when known, experiment procedure, parameter values, and separate Omnient and Camera Viewfinder raw measurement tables with `Run #` as the first column.
- Run 10 OFF/ON pairs per scenario unless the user changes the count. State the inclusion rule: both runs completed and their full-precision handshake durations differ by at most 10 ms by default, or the run-specific threshold explicitly requested by the user. For cold-connection runs, also require verified fresh HTTP/2 transport for both trials. Apply any explicitly requested run-specific outlier omission without changing the raw files.
- Do not put median or other summary statistics, comparisons, interpretation, an excluded-pair list, or artifact links in `report.md`. Keep the table values rounded to three decimals and preserve every original measurement in raw artifacts.
- Put per-trial transport evidence, early POST HTTP status, and available evidence of whether M1/M3 were in the handshake request, a concurrent early POST, or a later POST in `connection-reuse-audit.md`. Keep analysis of transport behavior and limitations there, separate from `report.md`.
- Put descriptions and direct links to raw CSV, JSON, logs, and available result bundles in `artifacts.md`. A result bundle need not be checked in if its exported evidence is retained.
- For new cold-connection runs, store per-trial Xcode and attachment-export logs in `logs/`, result bundles in `xcresults/`, and exported attachments in `attachments/`. Preserve earlier run layouts and keep the summarizer compatible with both.
- Describe an early POST HTTP 400 as a rejection. Client logs alone do not establish whether soft stickiness failed or requests arrived out of order.
- For cold-connection runs, update `summarize-cold-benchmark.py` when changing the generated layout, regenerate the documents, and verify them against the raw evidence. Do not use that generator on the earlier single-invocation run.
- For new Omnient delay sweeps, run 50 OFF/ON pairs at each of 0, 50, 100, 150, and 200 ms with binary encoding enabled unless the user specifies another count. Keep the 20 ms handshake-difference threshold and fresh-transport requirement. Use `run-relaunch-delay-sweep.py` and `finalize-delay-sweep.py` for new runs.
- Delay-sweep reports replace raw measurement tables with TTFA and TTFD histograms of paired ON-minus-OFF differences, with negative values meaning ON is faster. Include ON initial early POST HTTP 400 pairs when they satisfy the ordinary inclusion conditions; exclude unresolved early POST status and failed ordinary inclusion conditions. A verified absence of an early POST is eligible. Do not replace excluded pairs. Show the 400-pair count/rate over all requested pairs, histogram sample counts, and the number of included HTTP 400 pairs. For new runs, write this inclusive report directly to the benchmark run directory's `report.md`; do not generate a 400-excluded version or an `including-early-post-400/` variant. This user-requested histogram format and 400 rate override the default raw-table and no-summary-statistics rules for this experiment.
- Render histograms deterministically from retained evidence, with 10 ms bins and common bin edges across all configured delays for each metric. Retain full-precision paired differences, selection decisions, and bin counts in `histograms/`; link them from `artifacts.md`. Do not alter earlier reports when adding a new report mode.
- Finish runner edits before starting measurements; do not modify a shell script while it is executing. Resume recorded trials with `LENS_RESUME=1` after an infrastructure interruption. Preserve install/launch failures separately and never rerun completed pairs merely because they fail histogram inclusion.
- For long sweeps, `run-resumable-delay-sweep.py RUN_DIR [EXISTING_RUNNER_PID]` uses the run's `execution-settings.json` to resume safely and invokes `finalize-delay-sweep.py` after all trials are recorded. Only the specific destination-availability/system-notification failure before XCTest starts and before any result or measurement JSON is eligible for automatic recovery. Retain diagnostic and startup evidence before resuming; stop on unknown failures, failed device queries, or three unsuccessful recovery attempts for the same unstarted trial. Do not infer that the iPhone was locked from Xcode's generic unlock message. Record all scripts' hashes before they execute.
- For historical sweeps that already have a 400-excluded report, the supplemental `summarize-delay-sweep.py --include-early-post-400` mode remains available to preserve that original report. New sweeps use the main inclusive report (`--early-post-400-policy include`), and saved metadata preserves each run's policy when regenerating it.

- When elapsed benchmark time is requested or recorded, retain full-precision runner timestamps in `timing.json` and include total wall-clock duration in `report.md` and per-delay wall-clock duration in `artifacts.md`. State that launch, measurement, attachment export, and recovery gaps are included, while build and report generation are excluded. This requested duration overrides the default no-summary-statistics rule. Do not fabricate timings for older runs. Retain a cancellation report and `interruption.json` for a user-interrupted experiment; do not resume it.

- New sweeps use `executionProtocol: xcode-relaunch-batch`: one Xcode invocation per delay, one selected `testColdBinaryOmnientBatch` method, `-test-iterations 2*PAIRS -test-repetition-relaunch-enabled YES`, and a fresh app process per iteration. The persisted batch ordinal alternates OFF then ON; never group both settings in one repetition. Do not use retry or run-until-failure flags. Import originals by XCTest repetition number and verified ordinal/process identity with `import-relaunch-batch.py`; preserve shared stdout, original exports, and byte-range mappings. Stop for review on incomplete batches, preserve evidence, and never silently replace entered trials. The legacy recovery runners apply only to historical runs. Freeze runner, importer, generators, Swift sources, and compiled XCTest hashes before measurement.

- Original XCTest repetition numbers can differ from measurement ordinals after an unstarted test-runner launch. Associate original JSON by explicit ordinal, verify its batch UUID/process identity against stdout, and retain the original JSON/CSV repetition identity. Single-trial manifests omit repetitionNumber and represent one repetition. For a reviewed incomplete batch, import only its contiguous entered-and-exported ordinal prefix, retain the startup failure and original settings, and write `resume-review.json` with recordedTrialCount and mappingSHA256 before resuming only unentered ordinals. A lone remaining trial uses a separate Xcode invocation without repetition flags. Preserve earlier script versions and settings before amendments; never repeat a measured timeout or a pair excluded from histograms.

- Draw histogram bars without white borders: narrow full-range 10 ms bars can disappear behind border strokes. Place the full-range and zoom views in separate panels, never as an overlapping inset. Rendering corrections must preserve original measurements, selection, paired differences and bin counts. Record rendering hashes separately without changing frozen measurement execution settings.
